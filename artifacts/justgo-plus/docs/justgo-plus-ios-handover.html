1. Product and current scope

JustGo Plus is a portrait mobile app concept for Malaysian highway users. The reference screens cover sign-in, registration, identity steps, toll-related transactions, monthly e-Invoice, and account settings. The current app reproduces these screens in React Native. It also provides local demo profile, vehicle, Touch ’n Go, and RFID list actions.

The app runs as an Expo project in a pnpm workspace. Expo Router owns the route tree. The main screens are Home, Transactions, e-Invoice, and Me. Login and registration are separate routes. Several account settings are stack routes.

Use accurate language in product and support work. The screen can show “verified” sample flags. These are local demo values. They do not come from identity or account services. The default demo has mobile and email marked complete, identity not complete, and no real payment or vehicle record.

3. React Native concepts for iOS developers

React Native termiOS comparisonHow it works here
ComponentSimilar to a SwiftUI View, though it is a JavaScript or TypeScript function.Returns a UI tree built from native primitives such as View, Text, and Pressable.
PropsSimilar to initializer parameters for a view.Values sent from a parent component to a child. A child should not change its props.
StateSimilar to @State in SwiftUI.Use useState for local state. A state change asks React to render the component again.
HookNo direct UIKit equivalent. A hook shares stateful behavior between function components.Examples include useApp() and useProfileProgress().
ContextSimilar to an app-level environment value or dependency container.AppProvider exposes local app data and commands to nested routes.
StyleSheetSimilar in purpose to a centralized set of layout constants, but uses a JavaScript object.Uses flexbox layout. It is not UIKit Auto Layout, SwiftUI modifiers, or full browser CSS.
Route fileSimilar to a screen registered in a navigation coordinator.Expo Router derives routes from files. app/profile.tsx is the Profile screen route.
AsyncStorageSimilar to a simple local key/value store, not Keychain.Stores non-secret demo JSON. Never store passwords or tokens in it.

React controls the rendered UI from state. Avoid changing a view directly as you might update a UIKit view reference. Update state, then let React render the new view.

4. Architecture and data flow

The app uses MVVM plus a repository for local persistence. The goal is to keep layout, screen behavior, data types, and disk access in separate places.

Viewapp/ and components/
Displays state and forwards actions.
→
ViewModelviewmodels/
Holds form state and screen commands.
→
Modelmodels/index.ts
Defines app data types.
↔
Repositoryrepositories/
Loads and saves JSON.

Root providers

app/_layout.tsx loads Inter fonts and defines the root stack. It wraps the route tree with these providers:

  1. SafeAreaProvider exposes safe-area measurements.
  2. ErrorBoundary catches render errors and shows the error fallback.
  3. QueryClientProvider provides TanStack Query. No query is used now.
  4. AppProvider loads and shares local demo state.
  5. GestureHandlerRootView and KeyboardProvider provide gesture and keyboard support.
  6. StatusBar sets light status-bar content.
  7. RootLayoutNav declares the Expo Router stack.

Shared state commands

viewmodels/AppContext.tsx owns the shared AppData value. It exposes commands such as updateProfile, saveVehicle, deleteVehicle, saveCard, and setFilter. These functions create a new state object. They then call the repository.

// Current update pattern in AppContext.tsx, simplified for reading. const next = fn(dataRef.current); // Build a new snapshot. dataRef.current = next; setData(next); // Update React subscribers. await demoRepository.save(next); // Persist it on this device.

dataRef holds the newest snapshot for commands. React state triggers renders. The code updates memory before the asynchronous save finishes. It does not restore the old snapshot if the save fails. A storage failure can therefore leave memory and disk out of sync until the next load.

Example: edit a vehicle

  1. app/vehicle-form.tsx renders fields.
  2. useVehicleFormViewModel() stores the draft and form errors.
  3. validateVehicle() checks the draft.
  4. If it is valid, the view-model calls saveVehicle() from useApp().
  5. AppContext updates state and calls demoRepository.save().
  6. Views that use the changed data render again.

This flow keeps the screen from reading or writing AsyncStorage itself.

6. Core feature behavior

App entry and navigation

models/index.ts sets DEFAULT_DATA.signedIn to true. A clean install therefore opens Home in demo mode. If stored data says false, the tab layout redirects to /auth. “Explore demo” sets the local flag to true. Sign Out sets it to false. This flag is not an authentication token.

Login and registration

viewmodels/useAuthViewModel.ts holds phone, email, password, registration fields, form errors, and notices. It calls validation functions from services/validation.ts. OTP, email account login, and MyDigital ID show an unavailable-service notice. They do not send a request. The email password is cleared before the unavailable notice.

Registration has personal details and account details steps. MyKad, MyTentera, passport, email, and phone formats are checked locally. Submission says the account service is not connected. The ID number is not part of AppData. The user may copy some non-sensitive registration fields into the demo profile. This remains local demo state.

Home and onboarding progress

useProfileProgress() derives the five progress rows from the profile and local vehicle list. The demo profile begins with mobile and email marked complete. It shows two of five steps complete (40%). Identity, payment, and vehicle records are not confirmed by a backend. Payment and vehicle steps remain gated until the local identity flag allows them.

Transactions

useTransactionsViewModel() manages a selected date range and type/status filter. It persists filter selection. Its transaction array is intentionally empty. No request or data source populates it. The download action explains that it has no records to export and creates no file.

e-Invoice and Me

The e-Invoice tab reproduces onboarding progress. It does not call a tax or invoice service. Me offers local profile and list edits plus information screens. Some terms/privacy pages are summaries. They are not approved legal text.

7. Models, storage, and privacy

Current data shape

AppData has five top-level fields: signedIn, profile, vehicles, cards, and filter. The model also defines a Transaction type. The app does not currently hold transaction records in AppData.

export interface Vehicle { id: string; plate: string; make: string; model: string; color: string; createdAt: number; }

Profile includes the name, email, phone, nationality, document type, and three verification booleans. TollCard contains a local kind (tng or rfid), a label, and a number. That number is a demo card/tag identifier. It is not a bank card PAN or CVV.

Storage behavior

repositories/demoRepository.ts stores JSON under justgo-plus/demo-data/v1. On load, it merges the saved object with defaults and merges profile and filter sub-objects. This handles some missing fields. It does not validate the JSON with a runtime schema.

  • If the key is missing, DEFAULT_DATA is returned.
  • If valid stored JSON is partial, defaults fill selected missing values.
  • If JSON parsing fails, the repository throws. The context reports a local load error. The broken stored value is not removed automatically.
  • The key has a version suffix. No multi-version migration function exists.
  • Reset clears the key, then saves a fresh signed-out demo state.

Data safety

The code does not persist passwords, MyKad numbers, identity images, payment-card details, tokens, or server credentials. AsyncStorage is not encrypted storage. It is not Keychain. Do not add secrets to AppData.

Production requirement: Before adding real account data, define collection, retention, consent, deletion, server authorization, and encryption rules. Use an approved provider for sensitive identity and payment operations. Keep provider secrets on the server, not in the mobile bundle.

8. Dependencies and workspace management

The app is named @workspace/justgo-plus. It is part of the root pnpm workspace. The root preinstall script rejects npm and yarn installs. The workspace catalog manages selected shared versions. Use pnpm and preserve pnpm-lock.yaml.

pnpm --filter @workspace/justgo-plus run typecheck pnpm --filter @workspace/justgo-plus run dev

Install a dependency in this package only. Do not add app dependencies to the monorepo root. Check Expo SDK compatibility before adding a native module. A library can work in a web preview and still fail in Expo Go or an iOS native build.

@workspace/api-client-react and the shared API server are available in the workspace. The app has no current imports from the generated client. The shared API server is not needed for the current local demo. Do not infer a functioning backend from workspace presence.

TypeScript path alias

tsconfig.json extends Expo’s base TypeScript config. It enables strict checks and maps @/* to the app package root. Thus @/models means artifacts/justgo-plus/models.

Replit artifact configuration

.replit-artifact/artifact.toml defines the Expo service, root preview path, service port, and production commands. The managed service injects PORT and BASE_PATH. Use the managed Expo workflow. Do not hard-code its port in source code.

10. Development and build process

Development preview

The managed workflow is artifacts/justgo-plus: expo. It runs pnpm --filter @workspace/justgo-plus run dev. The package script starts Expo. It reads the Replit development domain and assigned port. It includes a non-fatal Replit Expo session sign-in step when the session secret exists. Do not remove that step or use it as an Expo token.

Use the workflow to start or restart Metro in Replit. Do not start another expo start process at the same time. For a physical iPhone preview, use Replit’s Expo preview and QR flow. This app has no committed native iOS project, so the source tree is not a direct Xcode workspace.

Type checking

pnpm --filter @workspace/justgo-plus run typecheck

This runs tsc -p tsconfig.json --noEmit for the mobile package. It checks TypeScript. It does not create an iOS binary or test the app on an iPhone.

Production artifact build

The artifact configuration runs pnpm --filter @workspace/justgo-plus run build. The script scripts/build.js:

  1. Reads a deployment domain and Replit ID from supported environment variables.
  2. Clears and creates static-build/ folders.
  3. Clears Metro caches and starts Metro if a healthy server is not already available.
  4. Requests Expo bundles and manifests for iOS and Android.
  5. Extracts and downloads assets, then rewrites bundle and manifest URLs to the deployment domain.
  6. Writes a timestamped bundle and platform manifests. It then stops a Metro process it started.

The production run command starts server/serve.js. That Node.js server uses built-in modules. It serves the static build, provides the app landing page, and returns the platform manifest when a request includes an iOS or Android expo-platform header. This is the configured Replit artifact build. It does not prove that App Store signing or App Store submission is configured.

11. Debug and maintain

Fast first checks

  1. Run the package TypeScript check.
  2. Check the managed Expo workflow log for Metro bundling errors.
  3. Reproduce in the Replit preview or on a device through the managed Expo preview.
  4. Trace the screen file to its view-model, model, and repository before changing shared behavior.

Common fault locations

SymptomFirst files to inspectReason
Blank screen at startupapp/_layout.tsx, workflow log, error boundary.Font gating, provider setup, module import, or route render can stop the UI.

State and persistence risks to remember

  • Types do not validate stored JSON at runtime. Add runtime validation and a migration before changing the persisted data shape.
  • Loading errors set a message, but saved malformed JSON remains on disk. A clear recovery action needs product behavior and user confirmation.
  • State changes before disk writes finish. If persistence rejects, memory is not rolled back.
  • Profile state uses local verification booleans. Do not connect sensitive actions to these booleans without server-verified status.
  • Some list editors accept identifier-like demo values. Avoid treating them as financial credentials.

13. One-day handover plan

  1. First hour: open app/_layout.tsx, app/(tabs)/_layout.tsx, and viewmodels/AppContext.tsx. Run the app workflow. Learn the route and provider tree.
  2. Hour 2: trace a profile edit from app/profile.tsx through useEntityForms.ts, services/validation.ts, AppContext.tsx, and demoRepository.ts.
  3. Hour 3: review models/index.ts and inspect actual AsyncStorage data behavior. Do not print user data to shared logs.
  4. Hour 4: review auth and the tab redirect. Confirm which actions are demo-only. Do not attempt a real sign-in until a provider is selected and configured.
  5. Hour 5: change a theme token in constants/colors.ts, run typecheck, and inspect the app preview. Revert the exercise after learning the path.
  6. Hour 6: read scripts/build.js, server/serve.js, and .replit-artifact/artifact.toml. Map Replit’s bundle flow. Do not add an Xcode project without confirming the desired build route.
  7. Hour 7: make a small isolated screen change. Test keyboard behavior, safe areas, tabs, and a supporting route on a real or managed iOS preview.
  8. Hour 8: record unresolved product decisions: authentication, eKYC, payments, toll data, e-Invoice, legal content, iOS release settings, and test scope.
